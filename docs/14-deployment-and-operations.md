# Deployment and Operations

## Local deployment

The recommended development deployment is three local Python services plus their Vite UIs.

```text
127.0.0.1:8000  MoodleMock
127.0.0.1:8001  PeppiMock
127.0.0.1:8002  MailerMock
```

## CSC deployment goal

The planned CSC phase is primarily an environment/deployment experiment. The prototype should first be proven locally and then moved to CSC with the minimum necessary dependencies.

## Deployment checklist

Before CSC deployment:

- confirm Python version;
- confirm Node.js version;
- install Python dependencies;
- install UI dependencies/build artifacts;
- confirm writable paths for JSON reports and snapshots;
- confirm ports/network policy;
- verify scheduler process behavior;
- confirm whether a persistent process manager is available;
- document environment variables/secrets separately;
- avoid putting API keys into Git.

## External AI providers

Model providers should be configured separately from mock data. The project has explored cloud and local options such as Gemini and Ollama.

For a student project, use free tiers or local models where practical and avoid adding billing information unless explicitly required and approved.

## Backup

Before major changes:

- commit source changes;
- preserve mock datasets;
- copy generated reports if they are useful as evidence;
- keep the working project ZIP as a backup.

## Resetting generated state

For a clean demonstration, reset or regenerate:

- `events/*snapshot*.json`;
- `events/events.json`;
- `reports/*.json` generated by the workflow;
- MailerMock message state if required.

Do not delete canonical mock source data unless you have a backup.
